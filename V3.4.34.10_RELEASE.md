# MarketPredictor v3.4.34.10

## Immediate fixes
- Fixed `/api/storage/overview` crash caused by missing `_format_bytes`.
- Added web-service cgroup memory telemetry to Storage so RAM pressure is not confused with PostgreSQL disk usage.
- Critical memory pressure blocks new heavy Market Data acquisition instead of risking another Render restart.
- Provider fetch concurrency throttles under memory pressure.
- Reduced default PostgreSQL pool sizing for a 1 GB web service.
- Market Data acquisition now uses a presence-only cache lookup and does not materialize stored candle JSON merely to find gaps.
- Provider futures are kept in a bounded in-flight window instead of submitting thousands of Future objects at once.
- Default in-flight write batches are smaller to reduce peak memory.

## Storage architecture recommendation
Keep PostgreSQL as the control plane. Store large 1-minute candle blobs and large historical export artifacts in a dedicated data plane: a Render persistent disk for the current single-service deployment, or an S3-compatible object store for the eventual web-service/background-worker split. Migrate incrementally with checksums; do not drop or recreate the production database.
