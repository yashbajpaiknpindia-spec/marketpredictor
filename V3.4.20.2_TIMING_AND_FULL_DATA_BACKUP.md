# MarketPredictor v3.4.20.2 — replay timing + complete application backup

## Replay timing correction

Terminal replay rows now show the actual duration and terminal timestamp for **completed, stopped, error, and cancelled** runs. Historical rows reconstruct elapsed time from `started_at`/`finished_at` when the newer timing columns were not persisted.

Active rows continue to show:

`elapsed · time left · estimated total · estimated finish`

Long/segmented parent replays now use the same work-unit definition as child replays: **simulated scan cycles**, not `stocks × scan cycles`. The parent ETA is updated while each child segment is running and a terminal stopped/error parent records its final duration.

## Complete application-data backup

The website now exposes **Export all application data** and **Import all application data**.

A backup is a gzip-compressed `tar` archive (`.mpbackup.tar.gz`) containing:

- every PostgreSQL `public` base-table row, exported with PostgreSQL `COPY`
- database column metadata and SHA-256 integrity hashes
- managed `data/`, `research/`, and `audit/` files
- the configured historical-export directory
- strategy IDs and the SHA-256 hash of `strategies.py` as provenance metadata

Secrets, `DATABASE_URL`, API keys, and application source code are intentionally excluded.

Backups and restores run asynchronously and use disk-backed processing so the web request does not construct the complete dataset in RAM. Restore is strict: the database table inventory must match the backup before any destructive replacement is performed, and replay jobs must be stopped first.

## Research replay preservation

The 20 strategy definitions in `strategies.py` are unchanged. Research Sweep remains independent and keeps the documented realistic execution mechanics while disabling portfolio-scarcity opportunity suppression. The research exit contract remains original-loss-stop-only until genuine net profit is available to protect with the profit trail.
