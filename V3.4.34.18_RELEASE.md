# MarketPredictor v3.4.34.18

## Rapid streaming diagnostics + non-blocking partial sessions

- Rapid remains production REAL-data-only and never synthesizes missing market candles.
- Session coverage is now a diagnostic marker, not a hard execution gate. Every real ticker-day that is actually available is scanned; missing ticker-days are skipped and recorded; a 0% session is recorded as unavailable and the run continues to the next session.
- Default Rapid marker is 1%. Higher markers remain available for stricter research diagnostics.
- 100% verified coverage remains the evidence-grade promotion/activation gate. Partial or empty sessions cannot be promoted as strong evidence.
- Fixed silent provider failure diagnostics: Rapid acquisition now captures missing INDstocks credentials, instrument-master failures, symbol-resolution failures, historical-window failures, empty provider responses, and reference-context warnings.
- Rapid now shows acquisition progress explicitly: provider symbol resolution, provider batch N/total, ticker-days verified, newly downloaded ticker-days, current session %, overall %, session 1m bars, elapsed/ETA, and current provider/data cause.
- Terminal exceptions are shown with an explicit `CAUSE:` prefix so a real failure is distinguishable from a normal partial-data diagnostic.
- A lightweight per-session manifest proof sample is retained: provider identity, provider symbol/instrument id, bar count, expected bars, checksum, and min/max timestamps. This survives raw-candle deletion and supports later real-data matching without retaining the full 1m candle payload.
- `market_data_coverage` is therefore retained during ephemeral Rapid cleanup; only the newly-created raw candle rows are deleted after a durable session checkpoint.
- Session fingerprints, coverage counts, missing-symbol samples, provider diagnostics and reference completeness remain persisted in Rapid evidence/checkpoints.
- Session-by-session ephemeral candle deletion and restart-safe durable checkpoints are preserved.
