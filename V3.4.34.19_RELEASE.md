# MarketPredictor v3.4.34.19

## Parallel Rapid Scan + live evidence + restart-safe batch checkpoints

- Rapid now schedules bounded parallel one-session workers behind a single parent run.
- The UI exposes a configurable scheduler wave (1/10/12/20/30 sessions) and memory-safe concurrent lanes (Auto/1/2/3/4). Auto derives the safe lane count from the current Render memory working set and keeps headroom below the 512 MB service limit.
- Scheduler waves are deterministically spread across the selected date range, so the lanes work on different period slices/months instead of concentrating every worker on adjacent sessions.
- A 12-session wave does not mean 12 Python workers at once: the requested wave is queued, while only the memory-safe lane count runs concurrently. This prevents a large batch from becoming a 512 MB process fork bomb.
- The parent run aggregates each completed child session into one strategy/session/stock/context evidence result and persists that aggregate after every completed session.
- Live status now returns only active/current-wave child-lane telemetry (session, stage, current ticker, provider batch progress, ticker-days and errors) without flooding the browser with all future shards.
- Rapid technical analysis, session-by-session P/L, and stock exposure/outcome tables update live after each completed session instead of waiting for the entire run to terminate.
- Resource estimation now reports concurrent lane count, scheduler waves, peak temporary candle storage across lanes, per-lane working-set estimate, peak web memory, and a rough speed-up upper bound. The live progress bar also combines completed sessions with fractional progress inside active lanes and derives a live ETA.
- Acquisition progress is durably written periodically; scanning checkpoints are persisted every bounded ticker batch. Existing verified real ticker-day cells are reused after restart, so a web-service restart/deploy update does not redownload completed cells or repeat completed sessions; the recovery worker relaunches the parent and only unfinished shards.
- Partial real data remains runnable; missing ticker-days are recorded, never synthesized, and 100% coverage remains an evidence-grade promotion gate rather than a run blocker.
- Ephemeral raw candle deletion remains default: after a session's evidence/checkpoint commits, newly created raw candle cells can be deleted while lightweight coverage/provenance proof is retained.
- The parent run is the only visible Rapid history/deletion target; shard rows remain internal implementation records.
