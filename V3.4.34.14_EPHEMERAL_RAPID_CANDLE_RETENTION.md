# MarketPredictor v3.4.34.14 — Ephemeral Rapid Candle Retention

Rapid Scan now supports two explicit raw-candle retention policies:

- `EPHEMERAL_DELETE_AFTER_SESSION` (default): acquire one trading session, verify it, scan it, commit the durable session checkpoint, then delete only the newly-created 1-minute candle/coverage cells for that session. Pre-existing canonical candles are preserved. Evidence/run records remain.
- `KEEP_TESTED_DATA`: retain the tested canonical 1-minute candles for later Replay or re-audit.

The ephemeral path is restart-safe. The session checkpoint records pending cleanup cells before deletion. After a web-service restart, the worker resumes the pending cleanup idempotently and then continues from the next completed-session checkpoint.

Rapid also stores a verified per-session dataset fingerprint before deleting the raw candles. At completion, those fingerprints are combined into the evidence dataset fingerprint, so provenance does not depend on the candles still being present.

The Rapid resource estimator now reports:
- estimated peak web-service memory for one streamed session;
- peak temporary candle storage for one session;
- storage that would be added if tested candles were kept;
- raw candle storage retained after the run under the selected policy;
- reference-cache allowance;
- estimated PostgreSQL usage after the run.
