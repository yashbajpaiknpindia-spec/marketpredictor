# V3.2.2 Data Provider / Fallback Audit

## Purpose
Fix the failures exposed by the 1-minute export audit without guessing provider identifiers or silently dropping datasets.

## Why INDstocks index requests were rejected
INDstocks' official historical-data contract accepts REST `scrip-codes` in `SEGMENT_TOKEN` form, e.g. `NSE_3045`, and a maximum of five instruments per request. Its index master exposes index `SECURITY_ID` values such as NIFTY 50 `40000001` and NIFTY IT `40000004`.

The prior exporter correctly tried `NSE_<index security id>` but, after some valid index tokens were rejected by the historical endpoint, it also retried undocumented `IDX_...`, `INDEX_...`, and bare-ID forms. Those retries could never be justified from the historical endpoint documentation.

### V3.2.2 fix
- Probe INDstocks with the documented `EXCH_ID` / `SEGMENT_TOKEN` form only.
- If the documented request is rejected or empty, stop guessing and move to a documented fallback provider.
- Preserve the exact provider error in `reference/index_probe.csv`.

## Upstox fallback contract
Official Upstox V3 historical candles use:

`/v3/historical-candle/{instrument_key}/{unit}/{interval}/{to_date}/{from_date}`

The official instruments JSON is used to resolve `instrument_key`. Upstox explicitly documents `NSE_INDEX|India VIX`, and its global-instruments file supports GIFT NIFTY and several global indices/indicators.

V3.2.2 uses Upstox for:
- India VIX / rejected NSE indices and sector indices;
- missing NSE equity days via `NSE_EQ|<ISIN>`;
- corporate actions via `/v2/fundamentals/{isin}/corporate-actions`;
- current company-profile sector/industry metadata (clearly marked non-point-in-time);
- quarterly income-statement reference data (never treated as causal without a filing timestamp);
- FII/DII cash activity via `/v2/market/fii` and `/v2/market/dii`;
- GIFT NIFTY and exact-match global instruments;
- recent instrument news, explicitly marked as only the official trailing-7-day coverage.

Upstox standard API calls are paced below its documented 500/minute standard-API ceiling and HTTP 429 is retried with bounded backoff.

## Dhan fallback contract
Dhan publishes a public instrument master. V3.2.2 resolves index security IDs from that file instead of requiring a handwritten mapping. Historical intraday requests use the documented:

- `exchangeSegment = IDX_I`
- `instrument = INDEX`
- 1/5/15-minute interval as applicable

Dhan is a third route if INDstocks and Upstox do not return the index and a Dhan Data API token is configured.

## Export auditability
Every requested provider route is explicit in the ZIP. Important files:

- `reference/index_probe.csv` — INDstocks documented index probe and provider error.
- `reference/fallback_provider_attempts.csv` — Upstox/Dhan success, empty, failed or credential-missing state.
- `reference/provider_capabilities.csv` — which fallback credentials were configured.
- `quality/dataset_status.csv` — primary and extra-dataset status, including fallback files.
- `quality/date_completeness.csv` — per-date universe coverage and research eligibility.
- `quality/data_anomalies.csv` — invalid/sanitized observations.

## Exporter data-quality fixes
1. Drop an exact 15:30 stock duplicate when it repeats 15:29.
2. Record negative volume and set it to zero for volume-feature safety.
3. Mark low-universe-coverage dates as partial/non-research-eligible.
4. Use Upstox to fill absent stock-days without replacing successful INDstocks day files.
5. Fix NIFTY Financial Services aliases while retaining exact-name resolution.

## Datasets still not honestly recoverable from these connected historical APIs
V3.2.2 does **not** invent:
- historical best-bid/ask or order-book replay;
- historical tick/trade prints when no licensed source is connected;
- true historical pre-open auction snapshots;
- point-in-time index/universe reconstitution history;
- point-in-time sector classification history;
- complete historical corporate news when an API only offers a trailing window.

Those remain `NOT_AVAILABLE` or `PARTIAL` rather than silently filled with current information.

## Credentials
Primary INDstocks credentials remain unchanged. Optional fallbacks require deployment secrets:

- `UPSTOX_ACCESS_TOKEN`
- `DHAN_ACCESS_TOKEN`

No token, MPIN, TOTP secret or password is written to the export ZIP.
