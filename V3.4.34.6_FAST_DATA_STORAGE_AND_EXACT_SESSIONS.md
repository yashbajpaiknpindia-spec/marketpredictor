# MarketPredictor v3.4.34.6 — Fast Data, Exact Recent Sessions & Storage

## Market Data acquisition
- Rapid/Evidence canonical acquisition remains **1-minute only**.
- Added exact recent-session selection: Latest 2 / 3 / 5 / 10 / 20 available sessions.
- Recent presets use the exact session dates present in the canonical data inventory rather than expanding to the entire calendar interval between first and last date.
- When no stored session exists yet, the selector safely falls back to the latest completed trading sessions for bootstrap acquisition.
- Market Data job history now exposes the exact selected session list, workflow progress, data coverage, heartbeat time, and stalled state.
- New acquisition attempts reconcile stale jobs before refusing a new job because an old database row is still marked running.
- A job with no heartbeat for 10+ minutes is marked `stalled`, never silently left as `running`; it can be resumed from the UI.

## Storage & deletion safety
- Added/expanded `/storage` to show PostgreSQL database usage, configured free space when a quota is explicitly supplied, per-table size/index size/row estimate, and rebuildable/reclaimable categories.
- Every storage category names its owning application page/component.
- Canonical market candles (`intraday_replay_candle_cache`) are explicitly protected from one-click cleanup.
- Cleanup requires an exact confirmation phrase and age cutoff.
- Rapid research cleanup removes runs and dependent evidence rows/snapshots but retains raw market candles.
- Replay cleanup protects active runs.
- Job metadata cleanup removes metadata only.
- Historical Export DB cleanup removes persisted archive chunks while keeping export metadata.
- Orphan coverage cleanup removes only non-COMPLETE coverage records that point to no canonical candle.
- Integrity auditing runs after cleanup operations and website-driven delete flows already covered by the application.

## Important storage note
PostgreSQL reports exact database/table usage, but the Render plan's quota is not exposed through PostgreSQL. The Storage page therefore shows plan-level free space only when `MARKETPREDICTOR_DB_STORAGE_LIMIT_GB` or `DATABASE_STORAGE_LIMIT_GB` is configured. It does not guess a quota.
