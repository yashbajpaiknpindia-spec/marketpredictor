# MarketPredictor v3.4.31.8 — Replay controls, cache durability, and Render memory guard

## Replay UI
- Added per-strategy ON/OFF switches for all 20 intraday strategies, defaulting all ON.
- Added All ON / All OFF controls.
- Strategy selection is replay-scoped and persisted in the run snapshot.
- Restored Delete for Recent Replay History rows; existing full Run History deletion remains available.
- Added visible replay protection controls:
  - Loss protection: default 0.125%.
  - Profit protection activation: default 0.30%.
- Protection values are persisted in the replay snapshot and shown in run configuration.
- Replay strategy/risk controls lock while a run is active.

## Historical-data reuse
- Replay checks the persistent Replay candle cache first.
- Replay then checks verified Export Data archive bytes.
- A covering Export Data metadata record without usable bytes is no longer treated as reusable data.
- If a covering archive cannot be restored/hydrated, automatic provider download is blocked to prevent silently downloading the same historical data again.
- Provider fetches remain limited to ticker-days genuinely missing from reusable sources.
- The Replay UI now distinguishes reusable archives from unavailable archive metadata.

## Render memory safety
- Large 1-minute replay segments remain bounded to one trading day per child.
- Runtime memory is checked during replay, not just at startup.
- On Render/cgroup-aware environments the guard uses whole-container memory, accounting for Gunicorn plus the isolated replay child process.
- The hard replay guard remains active even when the advanced memory acknowledgment checkbox is selected.
- Memory telemetry records the observed metric and safe hard limit in run status.
