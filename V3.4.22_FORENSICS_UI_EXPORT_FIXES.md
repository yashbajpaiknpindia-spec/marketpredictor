# MarketPredictor v3.4.22 — Replay Forensics / Evidence / Export Fixes

## Replay workspace
- Replay results are split into Overview, Trade Forensics, Strategy Evidence, and Run History views.
- Trade Forensics is server-paginated instead of rendering the complete trade ledger in one page.
- Extended replay child segments remain internal; user-facing views consolidate them under the logical parent replay.

## Trade-level audit fields
New persisted fields include invested value, exit value, holding time, profit-protection state, trailing activation state, trailing stop price at exit, management reason/version, and related configuration values.
Legacy trades that were recorded before management telemetry existed are reported as `UNKNOWN_LEGACY` rather than inferred.

## Strategy evidence
The Strategy Evidence API links a strategy's measured trades back to the logical replay runs that contributed them, including segmented replays. It reports run-by-run trades, win/loss, gross P&L, costs, net P&L, profit factor, failure mix, and management-telemetry coverage.

## Failure diagnostics
The existing deterministic diagnostics remain in place (including late entry, entry slippage, immediate adverse entry, false breakout, gave-back-profit, momentum fade, stopped-in-noise, and time-exit/no-follow-through). `NORMAL_LOSS` remains only where available telemetry cannot distinguish a more specific cause.

## Full application backup
The user-facing complete-backup control now uses the disk-backed asynchronous application-data backup worker. The PostgreSQL COPY serialization bug in the backup module was corrected to serialize SQL with the active cursor.
