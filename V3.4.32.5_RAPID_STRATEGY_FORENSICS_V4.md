# v3.4.32.5 Rapid Strategy Forensics v4

## Reliability
- Rapid Scan state is durable in PostgreSQL.
- A worker restart / Render web-service restart resumes from the last fully completed 1-minute trading session checkpoint.
- Stop requests are persisted in PostgreSQL and also signal the in-process worker.
- Delete is available from scan history and removes the saved run; a live worker exits at its next safe checkpoint.
- View works for running, stopped, and completed runs using either the latest checkpoint or the final result.

## Diagnostics
- The drawdown and profit markers are diagnostic only. They are not forced exits.
- Every signal is classified by natural path: pure loss, stop-first then recovery, profit-first then reversal, clean profit-first, or other mixed behavior.
- MAE and MFE remain explicit.

## Capital evidence
- Rapid Scan now accepts an evidence notional per signal.
- Session P/L and stock exposure are shown for the selected notional.
- Strategy rows also show independent-signal notional and hypothetical P/L.
- These are NOT combined portfolio results and do not replace the ₹2 lakh portfolio replay.

## UI
- Save settings stores the current Rapid Scan configuration in browser localStorage.
- Previous runs have View / Stop / Delete actions.
- Partial session results refresh while a scan is running.
- Synthetic seed remains internal; no seed control is exposed in the main UI.

## Performance note
The earlier local benchmark was a small 50-stock × 5-session calculation on the development machine. It was not a full 250-stock × 60-session Render Free benchmark. The current ETA is based on actual live Render throughput and is therefore intentionally more conservative.
