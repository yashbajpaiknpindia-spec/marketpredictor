# V3.2.2 Fallback Requirements

## Required behavior
- INDstocks is primary for stock/index candles.
- Only provider-documented identifier shapes may be sent.
- A rejected documented request must move to the next provider; do not brute-force undocumented token shapes.
- Every fallback attempt must be logged with provider, exact identifier where known, row count, status, and error.
- Existing successful primary day files must never be overwritten by fallback data.
- Multi-source data must be reconciled at day/timestamp level before use in research.

## Provider order
### Stocks
INDstocks -> Upstox `NSE_EQ|ISIN` for missing day files.

### NSE index / VIX / sector indices
INDstocks documented `NSE_<security_id>` -> Upstox official `NSE_INDEX|...` instrument key -> Dhan official security ID with `IDX_I` / `INDEX`.

### Corporate/reference context
NSE public route when accessible -> Upstox official fundamentals/market-information fallback.

### Global context
Stooq primary legacy route -> exact-match Upstox Global Instruments fallback. Similar-but-different benchmarks may not be silently substituted.

## Hard honesty requirements
- `CREDENTIAL_MISSING` is not `FAILED` and not `NOT_AVAILABLE`.
- `EMPTY` is not success unless the dataset is legitimately expected to contain no rows.
- Point-in-time history must not be synthesized from today's snapshot.
- Historical news with only seven-day API coverage must be tagged partial.
- Financial statement values without verified publication timestamps may not enter causal backtests.
- Historical microstructure must not be fabricated from OHLC candles.
