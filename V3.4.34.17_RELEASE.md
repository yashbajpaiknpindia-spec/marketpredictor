# MarketPredictor v3.4.34.17

## Rapid partial-real coverage + terminal-write fix

- Fixed Rapid terminal/status persistence failure caused by native dict values being sent directly to PostgreSQL JSONB columns (`can't adapt type 'dict'`).
- Rapid now keeps durable checkpoints and terminal error/result payloads even when the worker encounters an exception.
- Streaming Rapid no longer requires 100% ticker/day coverage to run a session. Default minimum real session coverage is 90%, configurable from the UI (85/90/95/100).
- Missing ticker-days are skipped, counted and recorded rather than aborting the entire session. No synthetic candles are substituted.
- Reference context gaps are diagnostic; they no longer prevent a usable real-data session from being scanned when enough real ticker-days are available.
- 100% verified coverage remains mandatory for evidence-grade promotion/activation. Partial scans are persisted as diagnostic evidence and explicitly marked blocked from promotion.
- Added lightweight per-session provenance: coverage counts, missing ticker sample, source contract, newly-created candle count, provider/fallback activity, reference completeness, and coverage fingerprint.
- Provenance survives the ephemeral raw-candle deletion because it is stored in the Rapid result/checkpoint and Evidence snapshot summary.
- Added local synthetic fixture test for the 20-strategy rapid evaluator with missing market/sector/daily context; synthetic generation remains test-only and is not part of Rapid production execution.
