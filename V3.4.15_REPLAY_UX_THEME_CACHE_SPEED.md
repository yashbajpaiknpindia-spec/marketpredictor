# v3.4.15 — Replay UX, Theme and Stored-Data Speed Fixes

## UI
- Added an explicit Light/Dark theme control with a persisted per-browser preference.
- Removed the Research Lab and Trading Automation tabs from the primary navigation. They remain accessible only through the `⋯` More menu.
- Replay status now distinguishes `USING STORED DATA`, `CHECKING STORED DATA`, and `DOWNLOADING` so an existing archive does not look like a provider download.

## Replay startup speed
- Replay start no longer waits for the informational data-plan request. The worker remains authoritative for correctness.
- Data-plan preflight has a short 3.5s timeout so a slow DB/cache probe cannot make the Run Replay button feel stuck.
- Stored-candle cache lookup is now one bulk PostgreSQL query for the full ticker/day matrix instead of one connection/query per ticker.
- Stored Export Data hydration now batches candle-cache writes instead of opening a PostgreSQL connection for every ticker-day.
- Replay loading progress now reports stored-archive reuse separately rather than sitting at ~2% while an existing ZIP is being prepared.
- Provider access remains missing-data-only; existing Replay cache and persisted Export Data are still preferred.

## Strategy / simulation safety
- No strategy definitions were changed.
- No candle resolution, entry timing, fill rules, slippage, costs, capital rules, exit rules, or strategy-independence semantics were intentionally changed.
