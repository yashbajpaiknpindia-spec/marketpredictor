# MarketPredictor v3.4.13 — Replay 23 bug fixes

This patch is based on the v3.4.12 replay-data-preflight/UX build and the forensic artifact from Replay #23.

## Fixed

1. **Replay headline return was wrong**
   - Removed the run-level sum of per-trade percentage returns.
   - Run `net_return_pct` is now the account return: `(ending capital - starting capital) / starting capital`.
   - Per-trade percentage returns remain unchanged in trade records.

2. **Existing Export Data was not matched to `.NS` replay tickers**
   - Export ZIPs store bare NSE symbols such as `DALBHARAT.csv` while replay commonly uses `DALBHARAT.NS`.
   - Replay now tries both forms and therefore reuses matching Export Data before provider fetches.
   - Existing Replay cache still has higher priority.

3. **Strategy stop profiles could silently widen the execution stop**
   - A strategy-specific stop can now tighten the execution risk, but cannot exceed the configured maximum stop-loss ceiling.
   - Entry/strategy definitions are unchanged.

4. **Profit protection was target-distance dependent**
   - Added an execution-only absolute protection trigger at **+0.40% favorable movement**.
   - At **+0.60% peak**, the minimum locked price becomes +0.40% gross.
   - At **+0.80% peak**, the minimum locked price becomes +0.60% gross.
   - Above +0.80%, the existing runner trailing logic remains active.
   - This is an execution/exit overlay; it does not change the 20 strategy definitions.

5. **Trailing-stop intrabar conflict ignored an already-armed trailing stop**
   - Replay conflict resolution now uses the effective stop including the stored trailing stop.
   - The conservative stop-first rule remains intact for ambiguous OHLC bars.

6. **Independent 20-strategy tournament could fail at runtime**
   - The tournament worker now resolves `data_source_mode` from the run settings instead of referencing an undefined local variable.
   - Each strategy remains isolated in its own virtual ledger.

7. **Forensic exports could lose the run settings/universe snapshot**
   - Run dictionaries now expose `settings_snapshot` and `universe_snapshot` directly.
   - The exact replay interval and exit-policy snapshot are persisted with new runs.

8. **Stopped runs now expose selected vs actually replayed days**
   - Status/list payloads include replayed dates/count and actual replay start/end.
   - A manually stopped 5-day run will not be mistaken for a completed 5-day run.

## Safety invariants kept

- 20 strategy definitions were not changed.
- Chronological candle processing is retained.
- Next-candle execution/fill semantics are retained.
- Costs, slippage, capital guard, position sizing, risk budget, and execution gates remain active.
- Export/replay cache reuse only avoids redundant downloads; it does not alter candles.
- The new protection rules are deterministic and recorded in the run snapshot.

## Validation performed

- `python -m py_compile *.py` passed for the source package.
- Static regression checks confirmed the account-return calculation, Export Data suffix matching, stop ceiling, +0.40% protection trigger, effective trailing-stop conflict handling, tournament data-source fix, forensic snapshot exposure, and actual replayed-date reporting.
