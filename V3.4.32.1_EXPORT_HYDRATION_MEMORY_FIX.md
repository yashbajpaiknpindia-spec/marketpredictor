# MarketPredictor v3.4.32.1 — Export Hydration + Render Memory Fix

## Root causes fixed

1. **Historical Export → Replay hydration silently produced empty candles.**
   The parser built a new `DatetimeIndex` while passing the original integer-indexed pandas Series into the DataFrame constructor. Pandas aligned the Series by index, converting OHLC values to `NaN`; the subsequent `dropna()` removed every row. Replay therefore found the export archive but reused zero stock candles.

2. **Persistent/archive state could become stale after PostgreSQL retention.**
   Older local `*.meta.json` or in-memory job records could still say `archive_persisted=true` after the DB retention policy evicted the archive chunks. The UI and Replay could then report a persistent archive that was not actually reconstructable. PostgreSQL is now authoritative for durability flags and storage mode when reconciling completed jobs.

3. **Export job listings now reconcile in-memory/local metadata with DB durability state.**
   This prevents stale `persistent` badges and makes the inventory calendar use the same truth as Replay hydration.
