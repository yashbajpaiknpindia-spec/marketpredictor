# v3.4.32.5 — REAL cache source lock + exit-priority fixes

## What changed

- Rapid Scan REAL/CACHED/STORED/DATABASE/HISTORICAL mode is backend-authoritative.
- REAL mode forces cache-only behavior; it cannot silently fall back to synthetic candles or provider downloads.
- REAL Rapid Scan performs an exact ticker-day cache coverage preflight before starting. Missing coverage blocks the run instead of biasing results.
- REAL Rapid Scan performs a final source-integrity check: completed REAL runs require every requested ticker-day to have come from the real cache and zero synthetic ticker-days.
- Synthetic Rapid candles remain in-memory only and are never written to the replay candle cache.
- Historical Replay profit/stop protection uses a deterministic intrabar path model and threshold crossing prices rather than waiting for the candle close.
- Live/paper exit snapshot highs/lows are filtered to bars at/after the position's entry time so pre-entry session extremes cannot arm or move protection.
- Existing cost-aware break-even and path-aware profit protection remain enabled.

## Important interpretation

Rapid Strategy Forensics is a diagnostic historical/synthetic path scan, not the final shared-capital ₹2,00,000 portfolio simulation. Final portfolio validation must use Intraday Replay with real cached candles, shared capital, position sizing, overlap controls, costs and slippage.

## Data provenance

The historical cache table predates source-provenance columns. Therefore legacy cached candles are treated as database-stored data, but their original upstream source cannot be proven from the old row alone. For strict provenance validation, use REAL cache mode plus exchange/provider reconciliation and attach source metadata to newly ingested cache rows.
