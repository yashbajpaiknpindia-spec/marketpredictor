# MarketPredictor v3.4.31.2

## Database bootstrap worker fix

This release fixes the remaining startup gap exposed by v3.4.31.1 diagnostics: a healthy PostgreSQL connection could be visible while schema bootstrap had recorded zero attempts.

### Changes
- Added an explicit, idempotent database-bootstrap worker supervisor.
- Added request-time supervision so `/healthz`, `/readyz`, `/api/db-status`, and `/api/db-bootstrap-status` cannot leave a dead/missed daemon worker invisible.
- Added worker liveness, start count, start/exit timestamps, last crash, and stall-threshold diagnostics to the existing bootstrap status contract.
- An unexpected bootstrap-thread exception becomes a terminal, explicit `bootstrap_worker_crashed` error instead of silently leaving `CHECKING`.
- A worker that stays alive but records zero schema attempts beyond the startup-stall threshold becomes `bootstrap_worker_stalled_before_schema`.
- Removed shared request-pool warm-up from the schema worker; schema migration uses its dedicated direct PostgreSQL connection and request-pool creation remains lazy.
- Kept the PostgreSQL advisory lock, bounded migration attempts, persistent schema fast path, and existing v1 bootstrap status contract.
