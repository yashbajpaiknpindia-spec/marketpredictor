# MarketPredictor v3.4.32.5 — Replay memory guard relaxed

## What changed

- The previous 220 MB estimate / 360 MB runtime thresholds were app-imposed safety gates. They are now **advisory by default** (`INTRADAY_REPLAY_MEMORY_GUARD_MODE=warn`) rather than replay-stopping conditions.
- `strict` remains available as an opt-in environment mode for operators who explicitly want the old fail-fast behaviour.
- Multi-day 1-minute replays continue to route to one-session child runs.
- 1-minute extended child runs now use a bounded **1-day history load plus 1 warmup day** instead of the global 3-day warmup, materially reducing per-child historical-candle memory while keeping a prior session available for indicators/context.
- Runtime memory observations are still recorded in the replay status; crossing the advisory reference produces a warning rather than `MemoryError` in `warn`/`off` mode. Render's own instance memory remains the outer boundary.

## Render context

Render currently lists its Free web-service plan at **512 MB RAM**. This build therefore avoids using a lower application-level threshold as a hard stop; the service still has to stay within Render's actual instance limit.

## Strategy / execution contract

No strategy definitions, entry logic, loss protection, profit protection, cost/slippage model, or research-sweep contract were changed by this fix.
