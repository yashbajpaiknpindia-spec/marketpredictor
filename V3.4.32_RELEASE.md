# MarketPredictor v3.4.32 — Unified 1m/5m Data Inventory Truth

## Fix
- Export Data and Intraday Replay calendars now share one verified Historical Export inventory helper.
- A completed export job record is never silently treated as reusable data unless its ZIP bytes are accessible locally or reconstructable from PostgreSQL.
- Unavailable completed archives are surfaced as amber `Export Data recorded, archive unavailable` dates instead of grey `No stored data`.
- Verified 1m archives appear as reusable coverage in both Export Data and Replay calendars.
- Verified 1m archives remain eligible as a local source for 5m derivation.
- Replay data-plan and calendar use the same verified export-archive records.
- Historical Export job/status APIs expose archive accessibility mode/reason.
- Export History distinguishes `persistent`, `local reusable`, and `archive unavailable`.
- Inventory summaries now distinguish verified complete dates from unavailable archive-record dates.

## Synthetic verification
- Verified synthetic 1m local ZIP: 3/3 trading dates visible to shared inventory.
- Unavailable synthetic 1m archive: 3/3 dates surfaced as unavailable, not missing.
- Synthetic 1m archive used for 5m inventory: verified and labeled as source resolution 1m.
- Frontend Replay and Export calendars both reference `/api/data-inventory/coverage`.

No strategy definitions, replay execution rules, loss/profit protection values, or database schema version were changed by this release.
