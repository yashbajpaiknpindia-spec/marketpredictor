# MarketPredictor v3.4.31 — DB Schema Lock + Bootstrap Diagnostics

## Root cause addressed

The schema bootstrap worker previously retried the entire monolithic `init_db()` migration indefinitely after a schema error. During overlapping Render deploys, more than one application instance could also enter the same migration path and compete for PostgreSQL DDL locks.

## Fix

- Added a PostgreSQL cluster-wide advisory lock around schema fast-path verification and full migration.
- A second application instance now reports `WAITING_FOR_MIGRATOR` and waits instead of launching a competing migration.
- Schema migration attempts are bounded by `DATABASE_SCHEMA_MAX_ATTEMPTS` (default 3).
- After the final failed attempt, bootstrap becomes a terminal `ERROR` state instead of looping forever.
- Existing/current databases still use the metadata fast path.
- Schema marker adoption now occurs while holding the advisory lock.
- Added a permanent Database Bootstrap panel to the homepage showing signal, PostgreSQL connectivity, schema state, current step, elapsed time, attempts, and the machine-readable diagnostic report.
- Added a Copy diagnostic button for sending the exact report into the engineering conversation.

## Signals

`READY`, `MIGRATING`, `WAITING_FOR_MIGRATOR`, `STALLED`, `ERROR`, `CONNECTING`, and `DISABLED`.
