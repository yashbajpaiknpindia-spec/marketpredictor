# MarketPredictor v3.4.31.1 — DB bootstrap state fix

## Root cause

The bootstrap status payload treated any state with a successful PostgreSQL connection and `db_ready=false` as `MIGRATING`. During the legitimate handoff between connection verification and the schema worker acquiring the migration lock, the API therefore reported a false migration state.

## Fix

- Added explicit `schema_pending` phase after connectivity verification.
- `db-bootstrap-status` now returns `CHECKING` while schema bootstrap has not actually started.
- `MIGRATING` requires an actual schema attempt / migration mode.
- `WAITING_FOR_MIGRATOR` remains separate.
- `/healthz` probes no longer overwrite an active schema migration state with `connected`.
- UI shows `CHECKING`, `MIGRATING`, `WAITING FOR MIGRATOR`, `STALLED`, and `ERROR` distinctly.

## Synthetic verification

The actual v3.4.31 bootstrap state-machine functions were executed with fake PostgreSQL connections covering fast-path success, lock waiting, bounded migration failure, active migration, terminal error, and the connection/schema handoff race.
