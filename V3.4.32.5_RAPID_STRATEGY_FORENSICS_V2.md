# MarketPredictor v3.4.32.5 — Rapid Strategy Forensics v2

## Purpose
Rapid Strategy Forensics is a fast screening layer before full Intraday Replay. It keeps all 20 strategy definitions unchanged and measures natural price-path behaviour.

## Primary diagnostic contract
The scanner does not enforce the selected drawdown/profit markers as exits. The markers are used only to classify chronology. Each signal is also classified using natural path evidence such as:

- pure loss: never reaches the selected profit marker and finishes negative
- stop-first recovery: selected drawdown marker occurs first, then the path reaches the profit marker
- stop-first then +1% / +2%: deeper recovery evidence
- profit reached but finished negative: profit opportunity / exit-capture evidence
- profit-first reversal: price reaches the profit marker and later finishes negative
- clean profit-first path
- MAE / MFE and raw cost-adjusted EOD outcome

## Data modes
### Real cached 1m
Reads the existing replay candle cache only. Missing ticker-days are counted and never silently filled.

### Synthetic market
Creates NSE-like 1-minute market, sector and stock paths entirely in memory. It does not insert synthetic candles into PostgreSQL. Synthetic mode is an engineering/stress/behaviour laboratory and is not historical proof of strategy edge.

Synthetic controls include deterministic seed and balanced/trend-heavy/choppy/volatile market character.

## Scan options
- 10 / 30 / 60 / 90 / 180 / 365 real sessions
- 500 synthetic sessions
- 25 / 50 / 100 / 150 / 250 stocks
- selectable diagnostic drawdown marker
- selectable profit marker
- synthetic seed
- synthetic market character

## Live observability
While a scan is running the UI shows:
- current ticker and date
- ticker-days completed / total
- 1-minute bars processed
- elapsed time / ETA
- current worker stage and explanation
- weekly checkpoint messages

## Export
The existing Rapid Forensics ZIP now includes the run configuration, strategy summary, weekly summary and bounded forensic samples. Synthetic provenance and diagnostic-only threshold semantics are included in the configuration.

## Resource safety
- one Rapid Scan worker at a time
- bounded 25-ticker batches
- weekly checkpoints
- synthetic context generated once per week chunk and reused across tickers
- segment-tree first-cross detection avoids repeated future-bar scans for every signal
- no synthetic candle persistence
- no AI calls
- no per-signal PostgreSQL inserts
