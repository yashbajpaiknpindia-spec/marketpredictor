# MarketPredictor v3.4.31.9 — Replay 1m Inventory / Durable Historical Export Fix

## Root cause fixed

Intraday Replay defaults to real 1-minute execution data, but the Replay stored-data calendar was hard-coded to request the 5-minute inventory endpoint. This allowed the Data Plan to correctly report 1m while the calendar simultaneously displayed 5m inventory, producing contradictory "no data" results.

The stored-data inventory also treated `archive_persisted=true` as the only reusable Export Data source. A large Export Data ZIP can be locally accessible on the worker while not being persisted in PostgreSQL, so that valid local archive was ignored by the inventory.

## Changes

- Replay inventory now requests the actual configured Replay interval; no hard-coded `5m` request remains in the Replay inventory loader.
- Replay inventory refreshes automatically when the Replay interval changes.
- Stored-data inventory recognizes verified, accessible local Export Data ZIPs even when they are not yet persisted in PostgreSQL.
- Inventory separately reports completed Export Data archive metadata whose bytes are unavailable on the current worker.
- Export Data PostgreSQL archive persistence default increased to 512 MB so a roughly 292 MB one-year 1m archive can be made durable.
- Only the newest two PostgreSQL-persisted Export archives are retained by default to control database growth.
- Added `Make Replay-persistent` action for completed local Export ZIPs; this promotes an existing ZIP into PostgreSQL without downloading market data again.
- Replay calendar wording now explicitly says it is a **verified stored-data inventory** and distinguishes Replay cache from verified Export Data archive reuse.

## Safety / scope

- Replay remains 1-minute canonical execution data by default (`INTRADAY_DATA_INTERVAL=1m`).
- No synthetic 1m bars are created from 5m data.
- Provider downloads remain missing-day-only after stored-source hydration.
- An inaccessible covering Export archive continues to block silent duplicate provider downloading in automatic Replay mode.
- Large replay memory protections are unchanged and remain hard limits.
