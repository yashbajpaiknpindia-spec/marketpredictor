# V3.2 Economic-Edge + Execution-First Engine

Version: `v3.2.1-opportunity-barrier-parity`

## What changed
- Economic hurdle is a first-class acceptance gate.
- Expected remaining move is required to clear mandatory round-trip costs with margin.
- Candidate families are evaluated independently before portfolio selection.
- 1-minute execution architecture is supported by design, while the current historical simulation remains 5-minute because the verified corpus contains no genuine historical 1-minute bytes.
- Anti-chase / late-entry controls are explicit.
- Execution telemetry fields are part of the trade ledger.
- Slippage is modeled separately from mandatory charges.
- Current research uses a conservative 2 bps round-trip slippage stress as an assumption only; it is not measured historical slippage.
- Live/production authorization remains OFF.
- V3.2.1 is the post-forensic-fix build. The application and research layers now share canonical side, barrier, economics and execution semantics.

## Simulation
Run only after the post-fix audit passes. The application does not auto-run research on startup.

Run:

```bash
python v3_2_research.py
```

Outputs are written to `research/v3_2/`.

## Important limitation
The verified corpus is 61 sessions, 225 symbols and 1,029,375 five-minute rows. It lacks genuine historical 1-minute, bid/ask, tick/order-book and point-in-time universe data. Therefore the current run can test signal/economic logic and 5-minute-compatible execution semantics, but it cannot prove ultra-low real-world slippage or millisecond execution.
