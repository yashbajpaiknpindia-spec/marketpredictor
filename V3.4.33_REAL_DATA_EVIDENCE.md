# MarketPredictor v3.4.33 — Real Data Evidence Pipeline

## Purpose
This release makes the Rapid/research path evidence-grade on real historical market data and creates one canonical cache/acquisition layer shared by Replay, Rapid, Paper and Live.

## Data acquisition
- Added a dedicated **Market Data & Evidence** page at `/market-data`.
- Supports calendar-year, H1/H2 six-month, custom-range and “available from year” requests.
- Canonical interval is 1-minute NSE cash-session data.
- Existing PostgreSQL candle-cache cells and completed Historical Export data are reused first.
- Only incomplete canonical ticker/day cells are candidates for provider acquisition.
- INDstocks is the primary historical source; Upstox-by-ISIN is used only for remaining gaps when configured.
- Symbol/provider mappings are persisted, including app symbol, provider symbol, instrument ID, ISIN, resolution method and error.
- Stale/renamed symbols can be resolved by ISIN before being marked unresolved.
- Every canonical cell is normalized and audited for exact session minutes, duplicates, invalid OHLC and checksum.
- Coverage diagnostics persist issue codes and aggregate issue counts.
- Acquisition jobs are durable and resume after a process restart; cache-first behavior prevents intentional re-download of complete cells.

## Rapid Scan
- Rapid UI no longer offers a synthetic market mode.
- Rapid execution is **REAL-data-only and cache-only**.
- Provider/network access is prohibited during Rapid execution.
- A Rapid run requires an exact 100% verified ticker-day matrix and the dataset fingerprint captured by the acquisition job.
- No partial dataset is treated as historical evidence.
- Synthetic Rapid worker/generator execution has been removed from `rapid_forensics.py`.

## Evidence registry
- Completed Rapid runs create versioned `strategy_evidence_snapshots`.
- Evidence is recorded by strategy and context: regime, volatility bucket, time bucket and side.
- Stored metrics include signals, wins/losses, win rate, net expectancy, profit factor, MFE/MAE and detailed path/exit diagnostics.
- Path-aware exit evidence records the +0.40% profit activation / protection shadow, strategy target/stop outcomes, trailing/force/EOD exits, profit-first/stop-first behavior, protected losses avoided, profit-then-reversal and stop-first-never-recovered statistics.
- Each snapshot stores the dataset fingerprint, source policy, changes/contract and configuration used.
- Evidence is research-only until explicitly activated.
- Only 100% verified, fully historical snapshots can be activated.
- Activated Rapid evidence is available to the blended Paper/Live selector through the existing trust-weighted evidence registry.

## Speed / reliability
- Symbol-map persistence is batched rather than writing one DB transaction per symbol.
- Rapid runtime telemetry remains coalesced to avoid UI-write overhead.
- Reference context uses the same cache-first acquisition layer.
- The acquisition worker is resumable after Gunicorn/Render restarts.

## Strategy contract
- The 20 strategy definitions are unchanged.
- No strategy is globally declared “good” or “bad” from one regime.
- Evidence is preserved by context so the selector can use regime/volatility/time/side-conditioned historical results.

## Validation
- 86 targeted regression/static tests passed after the changes.
- Additional real-data/evidence static tests pass.
- Jinja parsing and browser JavaScript syntax checks pass.
- A complete repository pytest run is blocked in the provided sandbox by missing optional runtime dependencies (`psycopg2` / `ijson`); this is an environment limitation, not a reported application assertion failure.
