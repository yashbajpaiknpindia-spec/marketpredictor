# MarketPredictor v3.4.20.3 — Replay phase ETA / segmented UI / research throughput fix

## What was fixed

### 1. Long Research Sweep progress was invisible during the expensive phase
Research Sweep runs in a spawned worker process. The previous phase telemetry lived only in the worker's in-memory runtime state, while the web process polled PostgreSQL. During historical-data loading and feature precomputation the DB row could remain at `0/total` and `ETA calculating` for many minutes.

v3.4.20.3 persists:
- runtime stage and stage detail
- data stage and data progress
- overall replay progress
- phase completed/total units
- phase rate and phase ETA
- estimated remaining/total time and estimated finish
- worker heartbeat

The UI therefore reports what the worker is actually doing before the first simulated scan cycle exists.

### 2. Feature precompute is now observable and faster
Feature preparation is reported in bounded symbol groups instead of appearing frozen for an entire day.

The MACD precomputation kept the exact previous 60-bar reset semantics but removed the repeated nested prefix calculations. A direct equivalence check against the previous implementation produced zero numerical difference for both MACD and MACD histogram on a random test series.

### 3. Historical candle fetching is bounded and parallelized
Missing stock-data batches are fetched with a small bounded worker pool (maximum four concurrent provider batches). Results are merged in the replay worker and database writes remain batched.

### 4. Segmented replays are user-facing as one replay
Past Runs hides internal segment rows. The parent replay shows only `segment X/Y`; internal segment/run IDs remain database implementation details.

New segment rows are linked with `batch_parent_id`. Existing segment rows referenced by a parent's `child_run_ids` are also filtered from the Past Runs list.

The parent status now receives the active segment's persisted phase and ETA, so it can show e.g.:

`segment 1/9 · feature precompute · phase ETA 00:54`

rather than exposing an internal run number.

### 5. Deleting a segmented replay cleans up its segments
Deleting a segmented parent also deletes all referenced internal segment rows and their cascaded trade/event data.

### 6. Coverage preflight is less misleading
The browser-side stored-coverage preflight timeout was increased from 3.5s to 15s. A timeout is now described as a still-running informational check instead of `signal is aborted without reason`. The worker-side data check remains authoritative.
