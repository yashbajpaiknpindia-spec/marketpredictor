# v3.3.2 Database Boot Diagnostics

This patch separates PostgreSQL network connection from schema migration.

## Why this exists
The previous boot log only printed `connection attempt #1 starting`. That message was emitted before `psycopg2.connect()` and the entire `init_db()` migration block, so it was impossible to tell which part was slow.

## New phases
- `connecting`: opening PostgreSQL connection
- `connected`: PostgreSQL connection + `SELECT 1` succeeded
- `migrating`: schema initialization running
- `ready`: schema initialization complete
- `error`: last phase failed; exact exception is returned by `/healthz`

## New health fields
`/healthz` now reports `db_connected`, `db_ready`, `db_status`, `db_phase`, `db_connect_ms`, `db_schema_ms`, `db_attempts`, and timestamps.

## Timeouts
- PostgreSQL connect timeout: 5 seconds
- PostgreSQL statement timeout during schema initialization: 30 seconds
- PostgreSQL lock timeout during schema initialization: 5 seconds
- Retry interval: 5 seconds

The UI database badge now distinguishes a real PostgreSQL connection from a still-running schema migration.
