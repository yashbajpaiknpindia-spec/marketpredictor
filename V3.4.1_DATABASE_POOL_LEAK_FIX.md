# MarketPredictor v3.4.1 — Database Pool Leak Fix

## Why this release exists

The v3.4.0 shared PostgreSQL pool had a lifecycle bug: `_PooledConnection.__exit__()` delegated to the underlying psycopg2 connection but did not return the connection to the pool. Code using `with get_db_connection() as conn:` could therefore leak a borrowed session until an explicit `conn.close()` happened.

The Render PostgreSQL logs showed persistent application sessions, so this needed to be fixed before treating the database as a slow connection problem.

## Fixes

- `_PooledConnection.__enter__()` now enters the underlying connection.
- `_PooledConnection.__exit__()` always returns the connection to the pool in a `finally` block.
- Pool creation uses `minconn=0`, so creating the pool does not open a second PostgreSQL connection merely to initialize the pool.
- The first API borrow opens one connection; subsequent requests reuse the returned idle connection.
- Added offline regression tests covering 100 repeated acquire/release cycles and exception handling.

## Local verification

- `python -m py_compile app.py` — PASS
- 100 pool acquire/release cycles — PASS
- Connections created across those 100 cycles — 1
- Connections borrowed at end — 0
- Exception path returns connection — PASS

A live PostgreSQL integration test cannot be performed in the build environment because it does not contain the user's Render database credentials/network access.
