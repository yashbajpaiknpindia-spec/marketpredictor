# MarketPredictor v3.4.23 — UI / Replay Evidence / Export fixes

## What changed
- Trade History and Export Data tabs render before their API loaders run and now show an inline error instead of appearing dead when a request fails.
- Trade History exit reconciliation is non-fatal; a market-data/exit refresh failure cannot prevent the historical rows from rendering.
- Export Data keeps the canonical disk-backed asynchronous full-application backup path; the browser no longer relies on the fragile single-request legacy export path.
- Intraday Replay shows recent logical parent runs on its landing page; child segments are folded into their parent for display.
- Regime compatibility is labeled as a predefined 0–100 strategy design prior, not a measured win rate or trade count.
- Strategy evidence shows total completed trades, wins, losses, optional flat/breakeven count, and the exact win-rate denominator.
- Recurring failure patterns are explicitly defined as repeated losing-trade observations (minimum four) across the selected replay lookback. Their parent sample size, win/loss/flat composition, pattern coverage, and attribution quality are shown.
- Failure attribution is conservative: exact strategy IDs are direct; safe legacy recovery may use exact strategy names or known strategy-ID pattern keys; otherwise the observation remains unattributed rather than being guessed.
- Exact zero-return trades are reported as flat/breakeven and are no longer counted as losses in the displayed win-rate denominator.
- Restored `historical_export.py` and `portfolio_engine.py`, which were missing from the previous package, so the distributed source tree is complete.

## Validation
58 tests pass in the offline build environment. The test environment lacks the installed Flask package, so production server import was not claimed; `requirements.txt` includes Flask 3.0.3 and ijson 3.3.0.
