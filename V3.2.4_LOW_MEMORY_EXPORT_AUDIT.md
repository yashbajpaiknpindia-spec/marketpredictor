# V3.2.4 Low-Memory Export Audit

## Incident diagnosis
The supplied Render log shows historical-export status calls succeeding through 07:25:05 UTC, followed by a new `gunicorn app:app` process at 07:25:56 UTC and a fresh worker boot at 07:26:21 UTC. The user separately reported Render's email reason as **memory limit exceeded**. The same export job remained queryable after restart, confirming the V3.2.3 PostgreSQL metadata persistence worked; the process performing the export was what died.

## Root cause in V3.2.3
For 1-minute exports V3.2.3 defaulted to:
- 2 worker threads;
- up to `workers * 2` = 4 pending/in-flight futures;
- up to 5 scrips per INDstocks historical call;
- up to 7 days per 1-minute response.

At ~376 minute rows/session, a worst-case in-flight candle count was approximately:
`4 futures × 5 scrips × 7 sessions × 376 ≈ 52,640 candle dictionaries`, in addition to HTTP response bodies, decoded JSON, ZIP buffers, the Flask application, pandas/scikit-learn state and PostgreSQL/client objects.

The memory governor ran after a completed response was consumed, so it could not prevent a transient allocation spike while `requests`/JSON parsing was constructing the response.

## V3.2.4 changes
1. **1m workers default: 1**.
2. **1m scrips per call default: 1** (env-overridable 1–5).
3. **1m max pending futures: 1**.
4. **Pre-fetch memory guard** runs before every provider call.
5. **Absolute RAM reserve:** 128 MB by default, in addition to earlier fractional thresholds.
6. **Earlier thresholds:** soft 60%, hard 78%; exporter pauses/refuses rather than approaching cgroup OOM.
7. **Heap release:** `gc.collect()` plus best-effort glibc `malloc_trim(0)`.
8. **PostgreSQL archive chunk size:** reduced from 4 MB to 1 MB by default.
9. **Fallback loop heap release** after each index/equity fallback operation.
10. **Start preflight:** a 1m export will not begin when the current web process lacks minimum response headroom.

## Peak transient reduction
New default worst-case candle objects in flight:
`1 future × 1 scrip × 7 sessions × 376 ≈ 2,632`.

That is about **20× fewer** in-flight candle dictionaries than V3.2.3's default path.

## Operational note
A Render process restart still terminates the Python thread that was actively fetching data. V3.2.4's goal is to prevent OOM restarts in the first place. Completed exports and job metadata remain persistent; an interrupted in-progress ZIP cannot be continued byte-for-byte after the underlying runtime is destroyed.
