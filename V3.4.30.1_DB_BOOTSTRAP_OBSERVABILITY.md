# MarketPredictor v3.4.30.1 — DB Bootstrap Observability

This release adds a single deployment/diagnostic contract for PostgreSQL bootstrap.

## Signals

`/api/db-bootstrap-status` returns one `signal`:

- `READY` — application schema verified and database-backed APIs can run.
- `MIGRATING` — the application is connected to PostgreSQL and the schema is being initialized.
- `STALLED` — no migration progress has been observed for the configured stall threshold (45s by default).
- `ERROR` — the latest schema attempt failed; the response contains the failing step and last error.
- `CONNECTING` — PostgreSQL connectivity is not established yet.
- `DISABLED` — `DATABASE_URL` is not configured.

## Deployment markers

Render logs contain machine-readable `[DB_BOOTSTRAP]` lines for `MIGRATING`, `READY`, and `ERROR` transitions. Schema statement failures also identify the exact statement number and compact SQL text.

## Endpoints

- `/api/db-bootstrap-status` — JSON diagnostic report; safe to query during migration.
- `/readyz` — readiness endpoint; returns HTTP 200 only after schema readiness. Keep Render's liveness/health check on `/healthz` so a long first-time migration does not cause a restart loop.
- `/healthz` and `/api/db-status` — continue to expose the same status data for the application UI.

## Reporting a failure

The deployment cannot initiate an unsolicited message to the ChatGPT conversation. When a deployment reports `ERROR` or remains `STALLED`, open `/api/db-bootstrap-status` and paste the JSON response into the conversation. It is designed to contain the exact diagnostic information needed to identify the failed schema step.
