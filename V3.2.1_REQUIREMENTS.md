# V3.2.1 Requirements — Post-Forensic-Fix Contract

## Purpose

This document defines the requirements that must hold before the V3.2.1 research simulation is considered valid. It is an engineering gate, not a profitability claim.

## A. Candidate discovery

1. Candidate discovery must not contain a universal time-of-day blackout. Any warm-up must be family-specific and justified by the indicators required by that family.
2. Percentage returns are fractional internally (`0.001 == 0.1%`). Thresholds must use the same unit system.
3. Discovery must be broad enough to identify early ignition, breakout, pullback, failed-breakout, mean-reversion and continuation situations before the approval layer.
4. Discovery must evaluate both LONG and SHORT.

## B. Labels

1. Entry is the next executable price after the decision timestamp.
2. Research must label target-before-stop, stop-before-target, timeout, MFE, MAE and time-to-event.
3. The predictive target must match the portfolio simulator objective; a six-bar closing return may be diagnostic but cannot stand in for a target-before-stop model.
4. Same-bar target/stop ambiguity must be resolved conservatively and identically in research and runtime.

## C. Economics

1. Brokerage, STT, exchange charges, SEBI fee, GST and stamp duty must be computed from turnover.
2. Brokerage must use the configured lower-of-rate/cap rule.
3. Mandatory costs and slippage must be reported separately.
4. The calculated economic hurdle must be the real acceptance condition; reporting a hurdle and applying a smaller floor is prohibited.
5. Expected gross edge must clear mandatory costs, execution stress and the configured safety margin.

## D. Strategy evidence

1. LONG statistics cannot be silently reused for SHORT.
2. Historical strategy evidence must be side-aware where the strategy outcome is directional.
3. Small validation buckets are diagnostic only; no tiny-sample rule may automatically erase all production candidates.
4. Context evidence must not be double-counted as independent evidence.

## E. Runtime parity

1. Backtest, replay, paper and live must share the same canonical side, risk, cost and exit semantics.
2. Paper positions must preserve LONG/SHORT direction.
3. Short target/stop, P&L, MFE/MAE, trailing and structural invalidation must be direction-aware.
4. Live routing must remain blocked until explicit promotion gates are passed.

## F. Execution

1. The intended flow is 5m structural setup -> 1m trigger -> execution-quality check -> order.
2. The current historical corpus cannot prove real 1m execution because it contains 5m candles only.
3. Real 1m data is required for paper/replay execution validation; quote data is required for live spread-aware execution.
4. Latency must be measured, not assumed.

## G. Portfolio simulation

1. At each decision timestamp, candidates are ranked by predicted net edge, not merely arrival order.
2. Concurrency must use the actual simulated exit bar, not a fixed signal-time duration.
3. Same-symbol duplicate exposure is blocked.
4. Maximum concurrent positions and daily trade/risk limits remain hard constraints.

## H. Required evidence before simulation

The post-fix audit must report PASS for every forensic defect category and must demonstrate that no fixed blind test has been modified merely to improve its historical result.

The simulation may still legitimately return `EDGE_NOT_PROVEN` or `NO_TRADE`. That is a research outcome, not an audit failure.

## I. Production data requirements

Required for eventual paper/live promotion beyond the current 5m compatibility layer:
- genuine historical 1m stock OHLCV;
- point-in-time large/midcap universe membership;
- point-in-time sector membership;
- valid intraday NIFTY and sector indices;
- India VIX or equivalent volatility state;
- corporate-action timestamps;
- Level-1 bid/ask for spread modelling;
- tick/order-book data where available;
- broker acknowledgement/fill timestamps.

## Status

`v3.2.1-opportunity-barrier-parity` is simulation-ready only after `V3.2.1_POST_FIX_AUDIT.md` reports PASS for all implementation defects. It is not live-authorized by this document.
