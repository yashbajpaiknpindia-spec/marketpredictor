# MarketPredictor v3.4.32.4 — Multi-day 1-minute Replay Segmentation Fix

## Failure addressed

A short 1-minute replay could be rejected by the normal replay memory preflight before the extended replay router took over.

Example failure:

`Estimated memory for this segment (~264.8 MB; hard runtime limit 360 MB) is too high ... this segment requested 3 day(s).`

The normal replay worker materializes the requested date range into its `history` structure before iterating through individual days. Therefore, allowing a multi-day 1-minute request through the single-run route defeats the bounded-memory contract.

## Fix

- Any multi-day 1-minute replay is now automatically routed through the extended parent/child replay path unless `force_single_replay=true` is explicitly supplied.
- 1-minute extended replay child segments are always exactly **1 trading day**.
- The extended batch-size calculation now calls the same authoritative `estimate_replay_memory_mb()` guard used by the child replay instead of maintaining a second approximation.
- For non-1-minute intervals, the largest batch is selected only when its authoritative estimate is below both the configured safety budget and the runtime hard limit.
- Existing 20 strategy definitions, execution logic, loss protection, profit protection, data-reuse policy, and capital accounting are unchanged.
