# MarketPredictor v3.4.34.3 — Market Data schema contract hotfix

## Production issue fixed
Render logs showed `/api/market-data/jobs` returning HTTP 500 because PostgreSQL reported:

`psycopg2.errors.UndefinedColumn: column "dataset_fingerprint" does not exist`

This was not a PostgreSQL connectivity failure. The request obtained a database connection and the database executed the SQL, but the deployed `market_data_jobs` table was older than the application query.

## Root cause
The persistent schema fast-path contract did not include the new Market Data / Evidence tables and columns. An older schema could therefore be treated as current when the schema marker matched.

## Changes
- Bumped schema contract to `3.4.34.3-market-data-schema-contract`.
- Added Market Data and Evidence tables to fast-path verification.
- Added required-column checks including `market_data_jobs.dataset_fingerprint`.
- Added an idempotent `market_data_jobs` schema guard to all Market Data acquisition/status/coverage/Rapid endpoints.
- The guard creates the table if absent and adds missing audit columns with `ADD COLUMN IF NOT EXISTS`.
- Old databases will now fail the fast path and run the full ordered schema migration when required.
- Existing PostgreSQL pool/keepalive behavior is unchanged; no connection-pool reset is triggered by this fix.

## Validation
- 20 focused schema/evidence tests passed.
- 132 static/synthetic bootstrap and application tests passed.
- Python compilation passed.
- Full test collection still requires the optional local packages used by three unrelated tests (`psycopg2`, `historical_export`, `portfolio_engine`) in this sandbox.
