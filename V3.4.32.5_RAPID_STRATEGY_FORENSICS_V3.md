# v3.4.32.5 Rapid Strategy Forensics — View/UX Hotfix

## Fixes
- Rapid Scan historical `View` now uses a compact status endpoint plus a separate result endpoint so a large result JSON or optional metadata cannot make a saved run fail to open.
- `View` falls back to the compact run-history endpoint during transient Render/DB connection or serialization issues, so an active run can still be opened and monitored.
- Completed result downloads read the stored result directly instead of depending on the large status response.
- Synthetic seed is no longer exposed as a primary UI control. Synthetic runs use the internal reproducible default seed; the visible controls stay focused on scan sessions, universe, market character, and recovery markers.
- Progress KPI now explicitly says `Sessions complete` to distinguish completed sessions from the live ticker-day progress inside the current session/week.

## Contract
The Rapid Scan drawdown/profit values remain diagnostic markers only. They are not forced exits. The scanner classifies natural price paths as pure loss, adverse-move recovery, profit-first reversal, clean profit path, and related recovery populations.
