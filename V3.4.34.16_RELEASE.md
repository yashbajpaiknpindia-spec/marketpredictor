# MarketPredictor v3.4.34.16

## Self-healing PostgreSQL bootstrap

This release changes database startup so a healthy PostgreSQL connection is not permanently failed because a new database is still creating its schema, a Render deploy overlap is holding the advisory lock, or a transient SSL/DDL interruption occurred.

### Startup behavior

- Fresh databases automatically run the full idempotent schema bootstrap.
- Schema creation retries indefinitely by default until the required schema contract is ready.
- `DATABASE_SCHEMA_FAIL_CLOSED=1` is required to restore bounded terminal-attempt behavior.
- Schema migration uses a dedicated direct connection with `statement_timeout=0`, `lock_timeout=0`, and `idle_in_transaction_session_timeout=0` so request-time limits cannot kill DDL bootstrap.
- A live bootstrap worker is never labeled `bootstrap_worker_stalled_before_schema` merely because the first schema attempt has not started yet.
- The bootstrap supervisor survives unexpected worker exceptions and retries automatically.
- Transient migration problems surface as `RETRYING`, `MIGRATING`, or `WAITING_FOR_MIGRATOR`; `ERROR` is reserved for explicit fail-closed terminal mode.
- Existing data-bearing databases retain the compatibility-first, non-destructive path.

### Safety

No database reset, drop, truncate, delete, or data migration was added by this release.
