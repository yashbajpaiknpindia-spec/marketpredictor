🎯 Strategy Dashboard Ten independent strategies. Each produces its own signal, confidence and risk profile; the selector picks whichever one is strongest for the current market regime. Win rates here are measured from recorded trades, never assumed — a strategy with too few trades is shown as unproven rather than being trusted.
Paper, live and replay are measured separately and never averaged — the same strategy can be profitable in one and lose money in another, and a blended number would hide exactly that.
💰 Capital & P&L breakdown Start with an amount, pick a period, and see exactly what happened to that money — how much of it was actually put to work, what it earned gross, what the costs took, and what you were left with. Paper, live and intraday replay are reported separately, never pooled.
Leave the dates blank for every recorded trade. Net P&L is after estimated brokerage, STT, exchange/SEBI charges, GST, stamp duty and the slippage reserve — the same cost model the engine uses to decide whether a trade is worth taking.

Runs whether or not auto-entry scanning is on, so a held position is never waiting on the next full scan to be protected.

Research Lab checks the strategy on old market days before you trust it on new days. It does not show tomorrow’s picks. It shows what worked, what failed, and what the system should avoid or boost in future scans.
Backtest = past simulation only. It checks old market days, records what would have worked, and builds lessons for future scans. It does not show tomorrow’s stock list.
How much history is enough? More trades per pattern gives a more trustworthy win rate (roughly ±18% margin of error at 8 trades vs ±5% at 100 trades), but calendar length matters separately: a strategy also needs to be tested across a real bull run, a choppy/sideways stretch, and ideally a real correction/bear phase, not just one market mood. 3 years is a reasonable starting minimum; 5-10 years gives a better chance of covering multiple regimes, though very old data for some symbols may be thinner or less reliable.
Data correctness for splits/bonus issues: Backtests fetch each stock's corporate-action history alongside prices. A confirmed stock split or bonus issue (common on NSE/BSE) is detected and excluded both from the data-integrity check and from any simulated trade whose holding window would straddle it, so a real split cannot be mistaken for a fake crash or a fake stop-loss hit.
Raw vs Learned: Raw replays the base strategy exactly as coded, with no pattern-memory or per-stock history applied — this is the honest control/baseline. Learned re-scores and filters the same test days using every lesson the system has recorded so far (pattern penalties, regime weighting, per-stock strength). Use "Compare Raw vs Learned" to run both on the identical window and see whether learning actually improved the result, and by how much. There is no target of a perfect win rate here — a small, consistent, positive edge across many trades (profit factor above 1.0, held up across regimes) is the realistic goal.

How stock selection works: “Quality stocks to scan” means the starting tradable universe. The app first removes inactive, illiquid, old-symbol, low-volume, low-turnover, or bad-history stocks. Then, on each old test date, it ranks the remaining quality stocks by bullish setup, volume confirmation, risk/reward, market type, past pattern behavior, and stock-specific history. It is not random.
Data integrity: New backtests record whether prices are raw or adjusted, the market-data source, and the candle-quality checks used before learning. Suspicious candle data is blocked so wrong prices do not become wrong learning.

Intraday Replay LabReplays the live intraday engine — not a separate strategy — continuously through a full historical trading day, with Start/Pause/Stop and the ability to view or delete past runs
Pick past trading day(s), and this runs the same scan → score → entry → position-guard → exit pipeline the live engine uses, tick by tick from market open to close, against real historical candles. It uses the same universe, the same strategy settings, the same position sizing, and the same evaluate_profit_protection_exit() function as Live/Paper — there is no separate "backtest strategy" here. It runs in the background (no request timeout), so you can navigate away and come back to check progress.

What this actually replays: your current Live/Paper strategy settings against historical data — "what would today's engine have done on that day," not necessarily what the engine actually did on that day if you've changed settings since. Universe/candle-interval/learning details for each run are shown below once it's running.
Research should measure every signal the strategy produced. A position cap silently discards later signals — including better ones — because the earlier ones happened to fill the slots first.
With positions unlimited, cash is what keeps the run realistic: positions are unlimited in number, but the total value of open positions can never exceed this replay's capital, and capital frees up again as positions close. Turn this off only if you want notional "what did the strategy find" counts, where the amount invested is not something the account could actually have funded.
Runs are capped at ~59 days back and 15 selected trading days per run. Universe, strategy thresholds, position limits, and cooldown all come from your current Live/Paper settings — a snapshot of them is saved with the run so a later settings change never changes what a past run says it used. "Capital for this replay" and "VWAP confirmation" are the two exceptions: leave them blank/"Match Live setting" to use your current Live/Paper values, or set them here to test a different capital size or VWAP rule for this run only — this never changes your saved Live/Paper settings. Uncheck "Apply learned adjustments" to run the RAW/BASELINE strategy with no strict-learning score adjustments or per-stock trade-history blocks, to see the strategy's own edge before any learned overlay; left checked, only trades that had actually closed before each replayed day count (no future leakage across a multi-day run). Large/Mid-cap filtering is on by default and required for both Live and Replay: the app auto-downloads and caches NSE's own NIFTY LargeMidcap 250 constituent list (or uses data/large_mid_cap_universe.txt if you've populated it as an override) — if neither is available the run refuses to start rather than silently testing the full universe. Uncheck "required" to allow an unfiltered Replay run on purpose; Live's own scanner has the equivalent INTRADAY_LIVE_CAP_FILTER_ENABLED env var (default on). Leave "Pre-scan pool size" blank to automatically match Live's own configured pool size (INTRADAY_PRE_SCAN_POOL_LIMIT) — this is what keeps Replay's stock selection identical to Live's; setting a smaller number here will be flagged with a warning since a stock Live would scan might not get scanned here. Entries go through the same final trade-plan gates Live uses (size-efficiency + cost gate) before filling at the next candle's open plus a small slippage allowance (not the signal candle's own price), and a fill that gaps beyond the max-chase limit is skipped, same as Live would. A run with an unusually large stock/day/interval combination will be blocked with a memory estimate unless "run anyway" is checked.
