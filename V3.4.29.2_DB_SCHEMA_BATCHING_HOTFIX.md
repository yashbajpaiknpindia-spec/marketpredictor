# MarketPredictor v3.4.29.2 — PostgreSQL schema startup batching hotfix

## Root cause

The Render PostgreSQL server was reachable and authenticating normally, but application schema initialization executed roughly 248 SQL statements as 248 individual client/server round trips. The observed Render timing of roughly 0.18 seconds per schema step made a fresh/slow startup take about 40–50 seconds.

The supplied PostgreSQL log shows successful authentication/authorization and normal disconnects; it does not show PostgreSQL rejecting or hanging connections.

## Fix

`_DiagnosticCursor` now renders each ordered migration statement with PostgreSQL `mogrify()` and executes statements in batches (25 by default). The original statement order and transaction semantics are preserved.

The batch size is configurable with:

`DATABASE_SCHEMA_BATCH_SIZE`

The database background initialization remains separate from HTTP serving, and application APIs continue to fail fast with `database_initializing` while schema setup is genuinely incomplete.
