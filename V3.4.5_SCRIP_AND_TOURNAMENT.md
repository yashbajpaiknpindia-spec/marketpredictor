# MarketPredictor v3.4.5 — Scrip Error Hardening + Independent 20-Strategy Research Tournament

## 1. INDstocks scrip-error hardening

- Index historical resolution now uses the instrument-master SECURITY_ID and probes only the documented REST `SEGMENT_TOKEN` shape (`NSE_<SECURITY_ID>`).
- The resolver no longer guesses undocumented `IDX_`, `INDEX_`, or bare-token variants.
- A rejected index code is cached as unavailable for the process/interval, so the same bad request is not repeatedly sent on every replay tick.
- Index-history rejection is treated as a provider-capability/data-context problem, not as a stock-data crash.
- `market_data.py` logs each unsupported index-history condition once and returns an empty frame, allowing replay/regime logic to continue with neutral index context.
- Equity historical scrip resolution is unchanged.

## 2. Research-only independent tournament

The new `20-Strategy Tournament` is separate from the normal selector replay.

Each of the 20 base strategies gets:

- its own virtual capital;
- its own open-position ledger;
- its own risk budget;
- its own trade-count and position limits;
- its own cost/slippage accounting;
- its own PF, expectancy, win rate, net P&L and drawdown statistics;
- both LONG and SHORT evaluations under the same base-strategy ledger.

There is deliberately **no cross-strategy selector, ranking gate, or capital sharing** inside the tournament.

Execution/risk/economics gates remain downstream so Research does not manufacture a signal by bypassing costs or risk:

- position sizing;
- minimum position-value/size efficiency;
- minimum expected-net-profit / cost economics;
- transaction costs;
- slippage and max-chase/fill-gap controls;
- risk budget;
- capital guard;
- max open positions;
- max trades/day;
- existing intraday profit-protection exit logic.

This means the tournament measures each strategy's own executable edge rather than merely counting raw signal occurrences.

## 3. Crash containment

- Strategy/ticker evaluation exceptions are isolated and counted in that strategy's `strategy_errors`/`error_samples`.
- One bad strategy, bad OHLC row, bad exit calculation, or failed trade-record insert is skipped without aborting the other 19 strategies.
- Runtime status is marked `tournament` and terminal worker errors are surfaced to the browser instead of leaving an infinite polling loop.
- Start/pause/stop controls are disabled consistently while a tournament is running.

## 4. Honest interpretation

The tournament's aggregate P&L is the sum of separate virtual ledgers and is **not** presented as one investable portfolio. Strategy-level PF/expectancy/drawdown should be inspected independently and then validated OOS with realistic costs before being used for live selection.

The tournament is not a claim that every strategy is independently profitable. It is a measurement framework that prevents one selector decision from hiding the underlying strategy-specific results.
