# MarketPredictor v3.4.29.1 — startup/loading hotfix

## Why this build exists

v3.4.29 kept the application shell available while the PostgreSQL schema initialized in the background, but database-backed API requests could still enter application code before the schema was ready. On a fresh/slow Render startup this could make the browser appear to buffer while a request waited behind schema work.

## Fix

- Database-backed `/api/*` requests now fail fast with HTTP 503 and `code=database_initializing` while schema initialization is incomplete.
- The HTML shell, `/api/market-status`, `/api/db-status`, `/api/system-status`, and `/healthz` remain available during startup.
- The frontend uses bounded `fetch()` timeouts for startup-critical status/API calls.
- Intraday Engine waits for `DB: Ready`, then retries automatically.
- Position Guard status is loaded only after schema readiness.
- A transient API timeout can no longer leave the initial Intraday page looking permanently stuck.

## Verification

Python compilation, JavaScript syntax, duplicate-ID checks, the existing v3.4.x static regression suite, and a Chromium smoke test are required before release.
