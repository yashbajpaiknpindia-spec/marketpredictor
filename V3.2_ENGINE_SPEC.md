# V3.2.1 — Quality-First / Execution-Aware Intraday Engine

## Objective
Build the next research/engineering version for NSE/BSE cash-equity intraday trading only, focused on one requirement:

> A trade is allowed only when the system has enough *remaining, executable, statistically supported* move to overcome mandatory charges, realistic execution friction, and a safety margin.

V3.2 must not be promoted because gross P&L is positive. It must prove positive net expectancy on unseen chronological data and then survive paper execution.

## 1. Core architecture

Raw data -> canonical 1m -> 5m structural bars -> market/sector regime -> stock state -> independent alpha families -> remaining-move model -> barrier probabilities -> execution-quality model -> exact cost hurdle -> portfolio deduplication -> risk -> 1m execution state machine -> post-trade attribution.

Live/paper/replay/backtest use the same decision semantics. Only the data/execution adapter changes.

## 2. Data requirements

Required for production-quality research:
- Genuine historical 1-minute OHLCV.
- Point-in-time Large/Midcap universe membership.
- Point-in-time sector mapping.
- NIFTY and relevant sector indices at 1m.
- India VIX or equivalent volatility state at 1m where available.
- Corporate-action/event timestamps.
- Bid/ask or Level-1 quotes for execution modelling.
- Tick/order-book data where available for live execution research.
- Broker order/trade acknowledgements and timestamps for paper/live latency measurement.

Never manufacture 1m history from 5m candles.

## 3. Signal philosophy

V3.2 does NOT ask: "Is this stock bullish?"

It asks:
1. Is there a specific setup?
2. Is the setup early enough?
3. How much move remains?
4. What is P(hit target before stop)?
5. What is expected MFE/MAE?
6. How long is the expected opportunity alive?
7. Can it be entered at a price that still clears the economic hurdle?
8. Is the opportunity independent enough to add portfolio value?

If any critical answer is weak: NO TRADE.

## 4. Independent alpha families

Keep families separate during discovery:
- Opening dislocation / opening range expansion.
- Compression -> expansion.
- Breakout with volume/relative participation confirmation.
- Pullback continuation.
- VWAP reclaim/rejection only when the setup is early and supported.
- Trend continuation using multi-timeframe structure.
- Failed breakout / failed breakdown.
- Mean reversion only in explicitly suitable regimes.
- Relative strength/weakness versus sector and market.
- Gap continuation/exhaustion.

Each family gets its own statistics. No family is promoted merely because it worked in-sample.

## 5. New V3.2 signal-quality gates

### A. Setup freshness
Reject if the move has already travelled too far before entry.

Track:
- distance from trigger,
- fraction of expected move already consumed,
- bars since trigger,
- volume already spent,
- extension from VWAP/ATR,
- distance from local structure.

### B. Remaining-move gate
Estimate expected remaining upside/downside from the executable entry, not from the signal candle.

Require:
expected gross move > mandatory costs + execution friction + safety buffer.

### C. Barrier probability gate
Estimate probability of:
- target before stop,
- stop before target,
- neither within time horizon.

Reject ambiguous setups even if directional probability is positive.

### D. MFE/MAE quality gate
A candidate must demonstrate sufficient historical favorable excursion relative to adverse excursion for its family/regime/side/time-of-day bucket.

### E. Time-decay gate
Every signal has an expiry. If the expected move does not start quickly, invalidate it rather than letting the position drift.

## 6. Economic hurdle — major V3.2 change

Do not use one arbitrary 5 bps slippage number as the definition of reality.

For every candidate calculate:
- buy turnover,
- sell turnover,
- brokerage,
- STT,
- exchange transaction charge,
- SEBI fee,
- GST,
- stamp duty,
- total mandatory cost,
- expected spread cost,
- expected market-impact cost,
- expected latency cost,
- expected adverse-selection cost,
- expected slippage,
- safety margin,
- expected gross P&L,
- expected net P&L.

Current NSE guidance lists non-delivery equity-sale STT at 0.025%, SEBI turnover fee at ₹10/crore, non-delivery stamp duty at 0.003% on the buyer, and GST at 18%; broker/exchange-specific charges must be parameterized rather than hard-coded. citeturn0search0

The model must calculate the exact broker/exchange cost schedule selected by the user rather than assuming every broker has identical charges.

### Economic acceptance rule

Accept only if:

Expected Gross Edge
- Mandatory Costs
- Expected Slippage
- Expected Market Impact
- Safety Buffer
> 0

And additionally:

Expected Net Edge / Risk >= configured minimum economic ratio.

The hurdle is dynamic by symbol liquidity, spread, time of day, volatility, and order type.

## 7. Slippage minimization architecture

The goal is not to pretend slippage is zero. The goal is to minimize it and measure it.

### Entry
- Do not chase an already extended candle.
- Prefer price-improving/limit execution when the setup remains valid and fill probability is acceptable.
- Use marketable limit orders with a hard maximum adverse price rather than unlimited market chasing where supported.
- Cancel stale orders when the setup loses freshness.
- Reprice only under strict rules; no repeated chasing.
- Reject trades where expected spread/impact consumes the edge.

### Execution-quality score
Before sending an order, calculate:
- spread in bps,
- spread/ATR,
- recent trade intensity,
- quote stability,
- depth if available,
- recent one-minute volatility,
- expected fill probability,
- expected adverse selection,
- order size / recent volume,
- distance to trigger invalidation.

### Order-size impact
Position sizing becomes execution-aware:
order participation = intended quantity / estimated near-term traded volume.

If participation is too high, reduce size or reject.

## 8. Ultra-fast execution architecture

The system should NOT rescan and recompute the entire market after every tick while already holding a position.

Use:
- event-driven market-data ingestion,
- incremental feature updates,
- precomputed rolling features,
- candidate shortlist cache,
- separate signal and execution loops,
- dedicated position manager,
- asynchronous logging,
- non-blocking UI updates.

### Target latency budget
Measure, don't assume:
- market-data receipt -> feature update,
- feature update -> signal decision,
- decision -> order creation,
- order creation -> broker acknowledgement,
- acknowledgement -> exchange/order-status update.

Every live/paper trade must receive a latency trace.

NSE supports Level 1/2/3 and tick-by-tick real-time data; Level 1 provides best bid/ask, Level 2 provides five levels of depth, Level 3 twenty levels, and tick-by-tick provides full order-book information. citeturn0search2

V3.2 should therefore support a tiered execution adapter: 1m data for research compatibility, Level-1 for practical quote-aware execution, and deeper/tick data when available and permitted.

## 9. 1m execution + 5m structure

5m answers: "Is the setup structurally valid?"

1m answers: "Is this the moment to execute?"

Execution trigger can require:
- 5m setup valid,
- 1m confirmation,
- price inside executable zone,
- spread acceptable,
- no excessive extension,
- expected remaining move still above hurdle.

Do not wait for a complete 5m candle if the 1m trigger already provides a causally valid entry.

## 10. Exit architecture

Use a hierarchy, not one universal exit:

1. Hard risk stop.
2. Structural invalidation.
3. Target when statistically justified.
4. Time stop.
5. Profit-protection / trailing logic only when expected continuation remains positive.
6. Execution/liquidity emergency exit.

The exit model must be trained/evaluated separately from entry quality.

## 11. Anti-chase controls

Reject/abort when:
- price has moved beyond maximum trigger distance,
- expected remaining move falls below hurdle,
- spread widens beyond threshold,
- volatility spikes without sufficient reward expansion,
- signal age exceeds expiry,
- entry would require chasing multiple consecutive bars.

## 12. Portfolio controls

Starting research capital: ₹2,00,000.

Initial controls remain configurable, not assumed optimal:
- max concurrent positions: 3,
- max trades/day: 4,
- daily loss cap: approximately 2%,
- per-trade risk: approximately 1%,
- duplicate/near-duplicate exposure blocked,
- sector concentration limit,
- market-direction concentration limit.

No-trade days are valid.

## 13. Regime engine

Build a regime vector rather than one regime label:
- market trend,
- market volatility,
- breadth,
- sector trend,
- stock trend,
- opening intensity,
- intraday volatility,
- liquidity state,
- dispersion,
- time-of-day.

Each alpha family declares which regimes it is allowed to operate in.

## 14. Research methodology

Chronological expanding walk-forward.

Each fold:
train -> purge -> validation -> purge -> unseen test.

Additional tests:
- untouched blind period,
- parameter perturbation,
- family ablation,
- placebo/permutation test,
- cost sensitivity,
- execution sensitivity,
- regime-by-regime test,
- side-by-side long/short test,
- time-of-day test,
- liquidity bucket test.

Do not repeatedly modify the same blind test until it becomes profitable.

## 16. New diagnostics

V3.2 must answer after every research run:

- How much gross alpha existed?
- How much disappeared to mandatory charges?
- How much disappeared to spread?
- How much disappeared to slippage?
- How much disappeared to market impact?
- How much disappeared because entries were late?
- Which signal family generated the edge?
- Which regime generated the edge?
- Which time-of-day generated the edge?
- Which symbols generated it?
- Did winners have enough MFE?
- Did losers experience early MAE that could have been cut?
- Were exits destroying profitable entries?
- Did the edge survive realistic execution?

## 17. Promotion gates

A V3.2 model remains locked unless all required gates pass:

- positive mean net expectancy on multiple unseen folds,
- positive aggregate net P&L after mandatory charges,
- positive under conservative execution stress,
- stable across parameter perturbations,
- no single symbol/day responsible for the edge,
- no single tiny sample bucket responsible for the edge,
- acceptable drawdown,
- untouched blind test positive,
- paper execution confirms latency/fill assumptions.

Otherwise: MODEL_NOT_AUTHORIZED.

## 19. Most important change from V3.1

V3.1 primarily established the data-first/alpha-first foundation but its tested hypotheses still produced gross edges too small to survive costs. The candidate-meta round had +0.0343% mean gross return versus 0.1061% mean mandatory fee before the additional 5 bps stress, and was rejected. fileciteturn14file0

V3.2 therefore moves the research objective from:

"Find a directionally good trade"

to:

"Find a sufficiently large, sufficiently early, sufficiently executable move whose expected net edge remains positive after all costs."

## 20. Non-negotiable principle

The engine must be willing to say NO TRADE even when a stock looks attractive.

The desired behavior is not maximum activity.

It is maximum quality per unit of risk and friction.


## V3.2.1 Post-Forensic Amendment

The forensic audit identified implementation defects that could make the zero-trade V3.2 result appear to represent a lack of market opportunities. V3.2.1 therefore requires:

- no global candidate start-time blackout;
- correct fractional-return units;
- side-symmetric strategy evaluation and side-specific evidence;
- barrier/MFE/MAE/time labels aligned with the simulator;
- a single canonical cost/economic gate;
- diagnostic-only small-sample family evidence;
- actual-exit-bar portfolio concurrency;
- research/runtime semantic parity;
- explicit short paper execution support;
- historical VWAP-to-matching-VWAP comparisons;
- simulation-independent post-fix audit before any new simulation.

`V3.2.1_REQUIREMENTS.md` is the authoritative checklist for these requirements.
